# 电子相册 · Air8607 实机示例

Air8607（1024×600 电容触摸屏）+ LuatOS AirUI 的全屏电子相册。照片通过 ESP32-C3 WiFi
网卡从 `img.he66.cn` 下载到 RAM，自动轮播，可旋转、可调亮度、可标记喜欢。

```text
┌──────────────────────────────────────────────────────────┐
│ ▌随机照片                               ● 在线            │
│  摄影 · 1024×1365 · 第 3 张                              │
│                                                          │
│                                                          │
│                  [        照片全屏显示        ]          │
│                                                          │
│                                                          │
│ 已缓存 · 下一张已就绪 268 KB    下一张 00:42             │
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━     │
│ [下一张] [暂停] [旋转 0] [喜欢] [来源：随机] [设置] [刷新] │
└──────────────────────────────────────────────────────────┘
```

点一下照片可隐藏顶栏/底栏和设置面板，再点一下恢复，方便纯看图。

## 功能

- **自动轮播**：默认 60 秒一张，可在「设置 → 切换间隔」拖动滑块改为 10–300 秒；「暂停」
  会冻结倒计时，「下一张」立即切换；底栏进度条显示当前这张还要停留多久。
- **旋转**：按 90° 循环（0°/90°/180°/270°）。180° 直接旋转；90°/270° 会按屏幕比例
  计算缩放，尽量铺满而不裁掉内容。
- **亮度**：PWM3 背光 10–100%，默认 100%，滑块松手立即生效；下限 10% 防止拖到全黑。
- **来源**：随机照片 / 喜欢照片两种模式，切换后立即换图；照片列表接口暂时没有接界面，
  只保留随机和喜欢两种轮播来源。
- **喜欢**：对当前照片调用 `react` 标记 `like` / `dislike` / `none`，「取消喜欢」会把状态
  改回 `none`；标记完成后底部状态栏会提示。
- **预取**：当前照片显示后立刻在后台下载下一张（写到另一块路径），倒计时结束时通常已缓存
  好，切换无等待；两张轮流占用 `/ram/album_a.jpg` 和 `/ram/album_b.jpg`。
- **固件版本检查**：C3 的 `hello` 会带上固件版本，1.1.0 起才支持照片下载。旧版本会回
  `unknown_command`，相册识别后停止重试，并在状态栏提示「C3 固件 1.0.0 不支持照片，
  请升级到 1.1.0」；C3 升级并重新上报 `hello` 后会自动恢复下载。
- **超时 600 秒**：单张照片从发起请求到收完允许最多 600 秒（Air8607 端和 ESP32-C3 端各
  自计时）。WiFi 慢或服务端卡住时不会永远等下去：中断后按 3 秒 → 6 秒 → 12 秒（上限
  15 秒）退避重试，仍失败则 30 秒后再试。
- **开机占位**：C3 还没连上或第一张照片还没下载好时，显示内置的 `/luadb/demo.jpg` 演示图，
  不会黑屏。

## 文件

| 文件 | 作用 |
| --- | --- |
| `main.lua` | 上电时序、RGB 屏初始化、GT911 触摸、背光、AirUI 启动 |
| `ui_album.lua` | 1024×600 界面：全屏照片、顶栏/底栏、设置面板、倒计时与预取调度 |
| `photo_client.lua` | UART2 协议客户端：命令发送、JSON 行解析、JPEG 二进制落盘、重试/取消 |
| `res/demo.jpg` | 开机演示图（1024×768，约 205 KB，烧录后位于 `/luadb/`） |
| `tp_gt911.lua` | GT911 触摸驱动（与 factory / puzzle 示例一致） |
| `exd_air8607_rgb.lua` | Air8607 RGB 屏驱动（与 factory / puzzle 示例一致） |
| `flash.sh` | 平铺当前目录（含 `res/`）并用 `luatos-cli` 烧录脚本区 |

界面（`ui_album.lua`）只通过 `photo_client` 的 `request/react/start` 接口取图和标记，
协议细节都在 `photo_client.lua` 里。

## 烧录

```bash
cd examples/air8607_photo_album
# 把 LuatOS-SoC_V1028_Air1603_102.soc 放到本目录，或：
#   SOC=/path/to/LuatOS-SoC_V1028_Air1603_102.soc ./flash.sh

./flash.sh                 # 自动选串口，只烧脚本区
./flash.sh /dev/cu.usbmodemXXXX full   # 连内核一起全量烧录
```

- 9 英寸屏把 `main.lua` 里的 `SCREEN_SIZE` 改成 `9`。
- 还需要 ESP32-C3 网卡固件：J110 `RX2/TX2` ↔ C3 GPIO4/5，见
  [`esp32c3_wifi_bridge/`](../../esp32c3_wifi_bridge/)。C3 固件 1.1.0 起包含照片代理，
  实测版本 1.1.1；烧录用该目录下的 `./flash_c3.sh /dev/cu.usbmodemXXXX`。

## 数据流

```text
Air8607                         ESP32-C3                       img.he66.cn
  PHOTO RANDOM <seq>  ───────▶  GET /api/photo/random?token=…  ───────▶
                      ◀───────  {"type":"photo","ok":true,…}\n
                      ◀───────  恰好 Content-Length 字节 JPEG
  /ram/album_a.jpg
  airui.image:set_src()
  REACT <seq> <id> like ──────▶  POST /api/photo/react  ──────────────▶
                      ◀───────  {"type":"react","ok":true,"state":1}\n
```

- 照片头是一行 JSON，后面紧跟**定长二进制**；只有收到 `len` 字节才算下载完成，避免 JSON
  和 JPEG 混在一起。
- `PHOTO CANCEL` 在超时、暂停换图或切换来源时发送，C3 会在 4 KB 分块之间检查并停止发送。
  取消后 Air8607 先进入短暂的「静默排空」状态，丢弃在途字节再回到行模式；C3 也会用一行
  `{"type":"photo","ok":false,"err":"cancelled"}` 结束半截数据流，双方重新对齐。
- 下一张照片会等当前这张收完或取消后才发，避免两条二进制流抢占 UART；C3 只处理最新一次
  请求，会丢掉旧会话残留的排队命令。

## 关于 token

照片接口的 token 只放在 ESP32-C3 固件的 `main/secrets.h`（已在 `.gitignore` 中），Air8607
的 Lua 脚本和本仓库都不包含 token。新环境编译 C3 前先复制模板：

```bash
cd esp32c3_wifi_bridge/main
cp secrets.h.example secrets.h
# 编辑 secrets.h，填入 PHOTO_TOKEN
```

## 验证状态

- 已做（2026-10-25 端到端）：C3 固件 **1.1.1** 已用 ESP-IDF 5.4.4 编译并烧录（rev0.3 ROM
  需按 256 字节分块写入，见 `esp32c3_wifi_bridge/esptool_256.py`）。相册日志实测：
  `hello 1.1.1 photo=1`、C3 联网 `172.22.22.119`，照片头带回正确的
  `id / w=1024 / h=1365 / len`，100–470 KB 的 JPEG 落盘 `/ram/album_a.jpg`、`album_b.jpg`
  并显示，预取和 60 秒自动切换（第 1 张 23.0 s 显示 → 第 2 张 83.5 s 显示）均正常。
- 已修复：`send_request` 把 `next_try` 置空后，tick 里的 `next_try or 0` 恒为真，导致
  Air8607 每秒钟重发一次请求、C3 不停取消下载。现在无响应 30 秒才重发，实测每张照片只发
  一次请求。
- 已修复：C3 之前用 `esp_http_client_get_header` 读响应头，这个 API 只查**请求**头，所以
  `id` 永远是 0（喜欢/不喜欢会发 `id=0` 被拒）。1.1.1 改为在 `HTTP_EVENT_ON_HEADER`
  回调里解析 `X-Photo-Id / Width / Height`，实测 `id=27051` 等正常。
- 已修复：取消后的在途字节会污染下一帧（表现为「丢弃过期图片帧」），现在用静默排空 + C3
  的 `cancelled` 结束行重新对齐；C3 也只处理最新请求，旧的排队下载不会再重放。
- 已修复：换图时新建的 `airui.image` 会排到顶栏/底栏之后，把按钮盖住导致点不到；现在照片
  放在**先于顶栏/底栏创建**的独立图层 `ui.layer` 里，无论重建多少次都保持在控制栏下面。
- 已修复：换图偶尔黑屏。JPEG 要等首次绘制才解码（实测 FPS 从 ~38 掉到 2，耗时几百毫秒），
  旧图先销毁就会露出黑底，尺寸越大停顿越明显。现在新图创建后旧图继续垫底 3 秒再由定时器
  销毁，切换期间屏幕保留上一张，不再闪黑。
- 已排查（2026-10-25）：连续抓 33 张照片日志，全部是合法的 baseline JPEG（SOI/EOI 完整、
  JPEG 尺寸与 `X-Photo-*` 头一致），PSRAM 占用稳定在 5–7 MB，没有任何解码失败日志，可以
  排除「图片本身损坏」。同一时期接口给设备返回的是 1024×600（高度不是 16 的倍数，走软件解码）。
- 已做：Air1603 的 `mcu.ticks()` 约 20 ms/tick（`mcu.hz()=50`），已按 `mcu.hz()` 折算，
  保活恢复为每 10 秒一次，轮播和 600 秒超时按真实秒数计时。
- 说明：1024×1365 这类宽高不是 16 倍数的照片，AirUI 会打印
  `skip HW, risky jpeg … not 16-aligned` 并改用软件解码，不影响显示；16 对齐的图走硬件解码。
- 待人工验收：旋转 90°/270° 的留边效果、亮度滑块手感、触摸「喜欢/不喜欢」的界面反馈
  （接口与 C3 返回已在上一轮用真实 API 验证并恢复数据）。
