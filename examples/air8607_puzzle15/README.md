# 数字华容道（15 Puzzle）· Air8607 实机示例

Air8607（1024×600 电容触摸屏）+ LuatOS AirUI 的完整小游戏：4×4 数字华容道，纯 Lua 实现，不依赖网络。带点击音效，屏幕亮度和音量可以在界面上直接调。

```text

│ ▌数字华容道                              ● 进行中         │
│  15 PUZZLE · 点击与空格相邻的数字块                       │
│                                                          │
│  ┌──────────────────────┐   本局数据                     │
│  │  1   2   3   4       │   步数           用时          │
│  │  5   6   7   8       │    42           01:23          │
│  │  9  10  11  12       │   ─────────────────────        │
│  │ 13  14  15  [ ]      │   设置                         │
│  └──────────────────────┘   屏幕亮度          100%       │
│                              ━━━━━━━━━━━━━━━━━━          │
│                             音量               70%       │
│                              ━━━━━━━━━━━━━━━━━━          │

│             提示：数字块只能滑入相邻的空格                │
```

## 玩法

- 点击与空格上下左右相邻的数字块，它会滑入空格，并播放一声点击音效。
- 把 `1 → 15` 按顺序排好，右下角留空即完成。
- 右侧显示步数和用时（500 ms 刷新）；完成时弹出结算卡片，可「再来一局」。
- 每次开机或「重新开始」都会重新洗牌，保证局面**一定可解**且不会太简单。
- 右侧「设置」里可拖动滑块调节**屏幕亮度**（10–100%）和**音量**（0–100%，0 即静音），松手立即生效。

## 文件

| 文件 | 作用 |
| --- | --- |
| `main.lua` | 上电时序、RGB 屏初始化、音频、GT911 触摸、背光、AirUI 启动 |
| `ui_puzzle.lua` | 1024×600 界面：标题栏、棋盘、数据/设置面板、完成弹层、计时器 |
| `puzzle_core.lua` | 纯逻辑：移动规则、完成判定、曼哈顿距离、可解性、洗牌 |
| `audio_click.lua` | 点击音效、音量控制、60 ms 节流、触摸总线恢复 |
| `exaudio.lua` | LuatOS 音频库（`factory/lib/exaudio.lua` v3.11，音效播放依赖） |
| `tp_gt911.lua` | GT911 触摸驱动（`factory/drv/tp/tp_gt911.lua`，含 `i2c_restore`） |
| `res/click.wav` | 点击音效（16 kHz / 16-bit / 单声道，32 ms，烧录后位于 `/luadb/`） |
| `exd_air8607_rgb.lua` | Air8607 RGB 屏驱动（与 factory / `air8607_c3_wifi` 示例一致） |
| `flash.sh` | 平铺当前目录（含 `res/`）并用 `luatos-cli` 烧录脚本区 |

逻辑和界面是分开的：`puzzle_core.lua` 不引用 `airui`，可以直接在 PC 上用 Lua 跑测试。

## 实现说明

- **可解性判定**（`puzzle_core.is_solvable`）：偶数阶棋盘 `(逆序数 + 空格所在行（从底部数）) % 2 == 1` 时可解；奇数阶只要求逆序数为偶数。这里主要用于自检，实际洗牌不依赖它。
- **洗牌**（`puzzle_core.shuffle`）：从复原状态做 `n² × 20 = 320` 步随机合法移动，天然保证可解；不满意的局面（已完成或曼哈顿距离 < 40）会重来，最多 20 次（`opts.rng` 可注入，方便测试）。
- **完成判定**：只检查 `tiles[1..15]` 依次为 `1..15`、`tiles[16] == 0`，不依赖步数或计时。
- **计时**：`mcu.ticks()` 按 `mcu.hz()` 折算成毫秒（Air1603 约 20 ms/tick，不能直接当毫秒用；不可用时退回 `os.time() * 1000`），完成时冻结；`sys.timerLoopStart` 每 500 ms 刷新一次。
- **可移动提示**：与空格相邻的数字块用亮色描边，其余为普通描边，触摸反馈用 `pressed_bg_color`。
- **点击音效**（`audio_click.lua`）：`exaudio` 以 `model = "dac"` 初始化，HT6873 功放使能脚为 GPIO73（高电平开启），播放 `/luadb/click.wav`。60 ms 内重复点击只响一次，避免快速滑动时叠音；`exaudio` 加载或初始化失败时只关音效，游戏和界面照常运行。
- **音量**：滑块 0–100，默认 70，调值调用 `exaudio.vol()`；0 等同静音。
- **亮度**：背光 PWM3（1 kHz）占空比 10–100%，默认 100%，滑块直接调用 `pwm.setDuty()` 即时生效；下限 10% 防止拖到全黑找不回来。
- **触摸与音频共存**：`exaudio.setup`、播放和调音量都会重配 I2C1，可能让 GT911 停在半事务状态（表现为「屏幕亮、点不动」）。`main.lua` 先初始化音频再初始化触摸，并在音频 `setup/vol/play_start` 之后调用 `tp_gt911.i2c_restore()` 恢复触摸总线。

## 验证状态

- 已做：Lua 语法检查（`luaparse`，全部 7 个 Lua 文件通过）；`puzzle_core.lua` 的 PC 端逻辑测试（1234 项断言：200 次洗牌全部可解、非终局、曼哈顿距离 ≥ 40；移动/相邻判定、完成判定、可解性、注入随机源可复现；n=2/3 洗牌；n=3 BFS 最短解交叉验证）；`ui_puzzle.lua` 的 mock AirUI 冒烟测试（45 项断言：控件数量与布局、可移动描边、无效点击、完成弹层与计时冻结、再来一局/重新开始、计时刷新、亮度/音量滑块与 PWM 夹取、有效移动和按钮触发音效、60 ms 节流、总线恢复）。
- 已在 **Air8607 + 10 英寸 1024×600 + GT911** 实机烧录脚本区（9 个文件，115172 字节）。启动日志确认：显示 `1024×600` 就绪、`audio_v2 DAC` 初始化、`click.wav` 解析为 16000 Hz / 16-bit / 单声道、GT911 触摸就绪、背光开启、局面生成（曼哈顿距离 42）。
- 未做：音效听感和实际播放延迟未人工验收（播放链路启动约 130 ms，益智游戏可接受）；亮度滑块的逐级亮度变化未做目测；界面布局和触摸手感仍建议在实机上确认。
